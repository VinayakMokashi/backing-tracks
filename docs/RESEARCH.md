## Research: midi-techniques
Designed the complete music-generation engine spec: a beat-based JSON dataclass song model with symbol-level chords; guitar strum simulation via 12-18 ms staggered string note-ons over real open/barre voicings (5 explicit pattern tables); 4 piano accompaniment patterns with a nearest-inversion voice-leading rule; tempo defaults plus verified GetSongBPM free API for auto-BPM (songbpm.com has no public API); transposition done at the chord-symbol level with full MIDI re-render (capo emulated as a guitar-note offset); and a verified GM drum map for an optional channel-10 drum track. Key facts verified live: GM programs are 0-indexed in code (nylon=24, steel=25, piano=0; 1-indexed 25/26/1 in human lists), GM percussion kick=36/snare=38/closed hat=42 on channel 10 (index 9), and GetSongBPM's API at api.getsong.co is free with an API key plus a mandatory backlink. Recommended write path: pretty_midi (seconds-based, ideal for ms strum offsets) rendered through FluidSynth + FluidR3_GM.sf2 to WAV.

Findings:
- [likely] 1. Internal song model (JSON-serializable dataclasses): Three levels, serialized with dataclasses.asdict() / loaded with a small from_dict.

@dataclass
class ChordEvent:
    symbol: str            # chart symbol AS WRITTEN, e.g. 'Am7', 'D/F#', 'N.C.' (shape symbol when capo>0)
    beat: float            # onset, 0-based, from section start, in beat units of the time-sig denominator
    duration_beats: float

@dataclass
class Section:
    name: str              # 'Intro','Verse 1','Chorus'...
    chords: list[ChordEvent]
    bars: int
    repeat: int = 1

@dataclass
class Song:
    title: str
    artist: str = ''
    sections: list[Section] = field(default_factory=list)
    bpm: float = 100.0     # ALWAYS stored as quarter-note BPM (matches MIDI tempo meta); UI converts for 6/8
    time_signature: tuple[int,int] = (4,4)   # tuple->list in JSON, restore on load
    key: str = 'C'         # shape key as printed on chart
    capo: int = 0          # semitones; sounding key = shape key + capo
    transpose: int = 0     # user shift in semitones, applied at render time, never mutates symbols on disk
    style: str = 'pop'     # selects strum/piano/drum pattern set
    source_url: str | None = None

Beat-unit rule: beat counts in denominator units (4/4 and 3/4 -> quarter beats 0..3 / 0..2 per bar; 6/8 -> eighth beats 0..5). Tick conversion: ticks = beat * PPQ * 4 / denominator (PPQ=480). Chord parsing: one regex, no heavy deps: ^([A-G][#b]?)([^/]*)?(?:/([A-G][#b]?))?$ -> (root, quality_string_passed_through_verbatim, bass). Only root and bass are ever transposed; quality text ('m7b5', 'sus4', 'add9') is opaque, which is exactly why symbol-level storage makes transposition trivial and lossless. Map quality to interval sets only at voicing time: {'':[0,4,7],'m':[0,3,7],'7':[0,4,7,10],'maj7':[0,4,7,11],'m7':[0,3,7,10],'sus4':[0,5,7],'sus2':[0,2,7],'dim':[0,3,6],'aug':[0,4,8],'add9':[0,4,7,14],'6':[0,4,7,9],'m7b5':[0,3,6,10]}; unknown quality -> fall back to major triad + log warning. 'N.C.' -> rest (no notes).
- [verified] 2a. GM program numbers for guitar/piano (VERIFIED, 0- vs 1-indexed): Human-readable GM lists are 1-indexed; the byte you put in a MIDI Program Change (and what mido/pretty_midi expect) is 0-indexed (value = list number - 1). Verified: Acoustic Grand Piano = 1 (list) = 0 (program byte); Acoustic Guitar nylon = 25 (list) = 24 (byte); Acoustic Guitar steel = 26 (list) = 25 (byte). Recommend steel (byte 25) as default for strummed pop/folk, nylon (byte 24) as a UI toggle for fingerpicked/ballad feel. Sources: https://en.wikipedia.org/wiki/General_MIDI , https://soundprogramming.net/file-formats/general-midi-instrument-list/
- [likely] 2b. Strum simulation mechanics: Each strum = one voicing (4-6 MIDI notes) with staggered note-on times. Downstrum: low string first, +15 ms per string (humanize each offset +/-4 ms; keep total spread 12-25 ms — 15 ms x 5 gaps = 75 ms full rake is audible but tight). Upstrum: high string first, and hit only the TOP 3-4 strings of the voicing (real technique; also thins the sound naturally). Velocity model: base velocity from the pattern table per slot; downs on beats 1 and 3 get the accent values (96-108), off-beat ups sit 15-25 below downs; add random +/-5 to every note; within one strum, decay 2-3 velocity per successive string. Duration: sustain each strum until the next strum in the pattern minus ~10 ms (values in tables below), so ring-out is automatic. Muted percussive hit ('x' in pattern notation): same voicing, all note durations 40-60 ms, velocity ~70, no stagger reduction needed (keep 10 ms stagger) — short gate on a steel-guitar patch reads convincingly as a chuck; no separate muted-guitar program needed. Timing math: with pretty_midi you work in seconds directly (easiest — slot_time = section_start + slot * 60/(2*bpm) for eighth slots, then add stagger in seconds). - [likely] 5. Transposition design (recommended: transpose symbols, re-render MIDI): Recommend symbol-level transposition + full MIDI regeneration, NOT shifting rendered MIDI note numbers. Reasons: (a) guitar voicings are shape-specific — an open-E voicing shifted +3 semitones is not a playable/idiomatic G and drifts out of register after a few semitones; re-picking voicings per new root keeps every key sounding like a guitarist; (b) piano voice-leading and LH register clamps must re-run; (c) the displayed chord sheet stays in sync with audio for free; (d) regeneration is milliseconds of work for a 4-minute song. Algorithm: new_root_pc = (pc(root) + t) % 12 for root AND slash bass (same t), quality string untouched; spell with flats if the target sounding key is F/Bb/Eb/Ab/Db/Gb or their relative minors, sharps otherwise.

Capo semantics (UG charts): chart shows SHAPE chords; sounding = shape + capo semitones. Emulate the capo for guitar realism: build voicings from the written shape symbols, then add capo semitones to every guitar MIDI note (a capo'd guitar is literally open shapes pitched up). Piano and drums ignore shapes and use sounding chords (shape + capo). When the user transposes by t: sounding target = original sounding key + t; simplest correct behavior is shape' = shape + ((capo + t) mod 12), capo' = 0 fallback — but the nicer 'auto-capo' option is: try capo' in 0..7, score each by how many chords land in the open-shape dictionary, pick the max; guitarists will recognize the result. Slash chords transpose both components; at render, bass overrides the lowest voice (guitar: substitute lowest string note; piano: LH plays bass pitch class in 36-47).

Risks:
- Chord-source scraping (Ultimate Guitar etc.) is aggressively bot-protected — even getsongbpm.com returned HTTP 403 to non-browser fetches this session; the retrieval module needs browser-like headers and a graceful paste-the-chart-manually fallback, and UG's ToS should be reviewed for the auto-search feature.
- GetSongBPM requires a visible backlink or suspends the API key without notice, and its database misses obscure/regional songs — treat auto-BPM as best-effort with a short timeout and never block generation on it; exact combined-lookup query syntax (type=both, 'song:...artist:...') was only confirmed from secondary/older docs and must be re-checked once an API key is issued.
- 6/8 tempo semantics are a classic bug source: MIDI tempo is per quarter note while musicians count 6/8 in dotted quarters — mislabeling the UI field yields half/double-speed renders.
- FluidSynth on Windows via pyfluidsynth has recurring DLL-discovery problems; the subprocess-CLI route is safer but its flags and winget package availability were not executed/verified this session (read-only task).
- Chord-symbol edge cases (unicode ♯/♭, 'N.C.', slash basses, exotic qualities like m7b5/add11, enharmonic respelling after transposition) will appear in real UG charts — the parser must pass unknown quality text through verbatim and fall back to plain triads rather than crash.
- Velocity/timing constants in the pattern tables are musically-informed starting points, not measured ground truth — expect one tuning pass by ear with the chosen SoundFont, since FluidR3_GM's guitar patches respond differently to velocity than other GM banks.

## Research: audio-rendering
FluidSynth is at v2.5.6 (released 2026-07-04) with official prebuilt Windows x64 zips on GitHub; there is no winget package, and the Chocolatey package lags at 2.4.7. The most robust Windows integration is invoking the fluidsynth CLI via subprocess with fast-render (-ni -T wav -F out.wav soundfont.sf2 in.mid) rather than pyFluidSynth ctypes bindings (maintained, v1.4.0 May 2026, but DLL discovery is fragile) or midi2audio (abandoned since 2016). For the SoundFont, GeneralUser GS v2.0.3 (Feb 2026, ~31 MB, free for commercial use, explicitly tuned for FluidSynth 2.3+/2.4) is the best pick over the much larger FluidR3_GM (~140 MB, MIT) and MuseScore's mono MS Basic. For WAV-to-MP3, skip pydub (last release March 2021, broken on Python 3.13+ due to the stdlib audioop removal unless audioop-lts is added) and call ffmpeg (winget id Gyan.FFmpeg, v8.1.2) directly via subprocess; target Python 3.12 for zero-friction compatibility, or 3.13/3.14 if pydub is avoided entirely. For browser preview, a plain <audio> tag on the server-rendered WAV/MP3 beats embedding html-midi-player (maintained, v1.6.0 July 2025, but CDN + Google-hosted soundfonts required for decent sound).

Risks:
- FluidSynth Windows release zip flavor choice: since 2.5.0 there are 'glib' and 'cpp11' variants; the cpp11 (OSAL) flavor is newer and less battle-tested — if odd behavior appears, fall back to the glib build.
- fluidsynth 2.5.6 was a security-fix release for malformed-MIDI/DLS parsing bugs; since this app renders MIDI files it generates itself the exposure is low, but always use 2.5.6+ rather than the older Chocolatey 2.4.7 build.
- GeneralUser GS license asks that you not deep-link the .sf2 download; if the app ever auto-downloads the font on first run, host it yourself or fetch from the official GitHub repo rather than hotlinking the author's site.
- Render-time figure (5-25 s for a 3-4 min song) is a reasoned estimate, not a published benchmark — validate on the target laptop early; if it is slower than expected, disable reverb/chorus (-R no -C no) or lower sample rate for previews.
- fluidsynth CLI fast-render is known to produce slightly different levels than realtime mode (FluidSynth issue #219) and can clip with default gain on dense arrangements — set -g explicitly (~0.5-0.7) and spot-check output for clipping.
- MS Basic and other .sf3 fonts require a FluidSynth build compiled with libsndfile/Vorbis support; the official Windows zips may not decode SF3 — stick to .sf2 fonts to be safe.
- If html-midi-player is added later, it requires internet at page load (jsDelivr CDN + Google-hosted soundfonts), which conflicts with a fully-offline local app unless assets are vendored; vendoring @magenta/music is nontrivial.
- Chord-retrieval side (Ultimate Guitar scraping) was out of scope here but is the most fragile part of the overall pipeline — UG has anti-bot measures; plan a manual paste-the-chords fallback.
